# B2 MeanFlow 训练发散问题说明

> 日期：2026-09-18

## 问题表现

B2 训练没有发生 CUDA、显存或程序异常，但损失从第 0 轮开始处于异常量级：

- 初始损失约为 $10^6$ 至 $10^{12}$；
- 日志中的最佳 `val/loss` 约为 $2.95\times10^6$；
- 后期 `train/loss` 和 `val/loss` 上升到 $10^{12}$ 以上；
- 模型发生严重数值发散，原 checkpoint 不可用于 B1/B2 对比。

## 问题原因

连续时间嵌入的频率方向写反：

```python
frequencies = exp(+log(10000) * ...)
```

这会产生从 $1$ 到 $10000$ 的递增频率。B2 的 MeanFlow 目标通过 JVP 对时间求导，高频时间嵌入使时间导数被大幅放大：

$$
2\pi\times10000\approx62832.
$$

B1 不需要对时间嵌入求导，因此该问题在 B1 中没有直接表现为损失爆炸。

修复前诊断结果：

- 时间 JVP RMS：`3286.54`；
- MeanFlow 目标 RMS：`1971.98`；
- 初始 MSE：`3.89e6`。

## 解决方法

将时间嵌入改为标准递减频率：

```python
frequencies = exp(-log(10000) * ...)
```

修复后诊断结果：

- 时间 JVP RMS：`0.293`；
- MeanFlow 目标 RMS：`2.96`；
- 初始 MSE：`8.81`。

同时增加时间嵌入导数上界测试，防止该问题再次出现。全部模型测试通过：

```text
29 passed
```

## 后续处理

1. 放弃已经发散的 B2 checkpoint，不从该 checkpoint 继续训练；
2. 使用修复后的代码重新训练 B2；
3. 严格对比 B1/B2 时，两者应使用修复后的相同时间嵌入重新训练；
4. 保持优化器、学习率、batch size、训练轮数、随机种子和数据划分一致。
