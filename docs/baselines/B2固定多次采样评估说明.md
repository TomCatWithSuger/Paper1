# B2 固定多次采样评估说明

> 更新时间：2026-09-20

## 1. 问题背景

B2 条件 MeanFlow 的单次损失依赖两类随机变量：

1. 高斯噪声：

   $$
   \epsilon \sim \mathcal{N}(0,I);
   $$

2. MeanFlow 时间区间：

   $$
   0 \le r \le t \le 1.
   $$

因此，即使模型参数和验证数据完全不变，只要重新采样噪声或时间区间，同一个 batch 也可能得到不同的 loss。

## 2. 原本的评估方式

修改前，训练、验证和测试阶段都通过一次 `model_step()` 计算损失：

```text
训练：随机采样，K=1
验证：随机采样，K=1
测试：随机采样，K=1
```

每次调用都会重新随机生成：

- 一组高斯噪声 $\epsilon$；
- 一组区间起点 $r$；
- 一组区间终点 $t$；
- 决定是否令 $r=t$ 的随机掩码。

这种方式对训练是合理的，因为持续改变噪声和时间区间可以覆盖更多训练目标。但是，将同样的随机单次估计用于验证和测试，会使记录的指标同时受到以下两部分影响：

$$
\text{观测 loss}
=
\text{模型误差}
+
\text{随机采样波动}.
$$

实际表现为：

- 相邻 epoch 的 `val/loss` 可能明显波动；
- 相同 checkpoint 重复验证时可能得到不同结果；
- EarlyStopping 可能把随机下降误认为模型改善；
- ModelCheckpoint 选出的“最佳模型”可能受单次随机采样影响；
- 单次 `test/loss` 对模型真实性能的代表性不足。

修复时间嵌入数值问题后的 B2 训练已经不再发散，但运行 `2026-09-18_20-33-02` 中的验证损失仍存在较明显波动。该现象与验证阶段采用随机单次 Monte Carlo 估计相符，因此需要单独降低评估方差。

## 3. 修改后的方案

当前采用以下策略：

```text
训练阶段：随机采样，K=1
验证阶段：固定采样，K=4
测试阶段：固定采样，K=8
```

### 3.1 训练阶段保持不变

训练阶段继续继承原有 `training_step()`，每个 batch 只执行一次 `model_step()`，并使用全局随机状态生成噪声和时间区间。

这样不会增加训练步骤的计算量，也不会减少训练过程中随机目标的覆盖范围。

### 3.2 验证阶段固定采样四次

对每个验证 batch，使用四个确定性随机种子分别计算损失，然后取平均值：

$$
\mathcal{L}_{\mathrm{val}}
=
\frac{1}{4}
\sum_{k=1}^{4}
\mathcal{L}_{\mathrm{val}}^{(k)}.
$$

同一个 `batch_idx` 在不同 epoch 中会使用相同的四组：

- 高斯噪声；
- 时间区间；
- 等时刻采样掩码。

因此，验证指标的变化主要来自模型参数变化，而不是每轮重新随机采样。

### 3.3 测试阶段固定采样八次

测试阶段使用八组固定采样：

$$
\mathcal{L}_{\mathrm{test}}
=
\frac{1}{8}
\sum_{k=1}^{8}
\mathcal{L}_{\mathrm{test}}^{(k)}.
$$

测试随机种子额外增加 $10^9$ 的偏移量，使测试阶段与验证阶段使用不同的随机流，避免验证和测试共享同一组噪声及时间区间。

## 4. 具体实现

### 4.1 新增配置

`configs/model/conditional_mean_flow.yaml` 中新增：

```yaml
validation_sampling_count: 4
test_sampling_count: 8
evaluation_seed: 12345
```

含义如下：

| 配置项                      |  当前值 | 作用                          |
| --------------------------- | ------: | ----------------------------- |
| `validation_sampling_count` |       4 | 每个验证 batch 的固定采样次数 |
| `test_sampling_count`       |       8 | 每个测试 batch 的固定采样次数 |
| `evaluation_seed`           | `12345` | 固定评估随机流的基础种子      |

### 4.2 显式随机数生成器

`_sample_time_intervals()` 和 `model_step()` 增加了可选的 `torch.Generator` 参数。训练阶段不传入生成器，行为仍然是随机采样；验证和测试阶段传入手动设置种子的生成器，以复现噪声和时间区间。

每次评估采样使用的种子为：

$$
\text{seed}
=
\text{evaluation\_seed}
+
\text{seed\_offset}
+
\text{batch\_idx}\times K
+
\text{sample\_idx}.
$$

其中：

- 验证阶段 `seed_offset = 0`；
- 测试阶段 `seed_offset = 1,000,000,000`；
- `sample_idx` 的范围为 $[0,K-1]$。

### 4.3 多次损失平均

新增 `_evaluation_loss()`，针对同一 batch 创建 $K$ 个固定生成器，分别调用 `model_step()`，最后对损失取平均。

`validation_step()` 使用 `K=4`，`test_step()` 使用 `K=8`。训练阶段没有调用该函数，因此仍然是随机 `K=1`。

## 5. 修改后导致的情况

### 5.1 已确认的结果

当前单元测试已经确认：

- 验证采样次数为 4；
- 测试采样次数为 8；
- 改变 PyTorch 全局随机状态后，同一个 batch 和 `batch_idx` 的固定评估 loss 完全一致；
- B2 的 JVP 目标计算和反向传播保持正常；
- B1/B2 相关测试共 15 项通过；
- 修改文件通过格式、静态检查和安全检查。

这说明固定采样机制已经生效，并且没有改变 B2 的训练梯度流程。

### 5.2 对指标的影响

修改后，预期会出现以下变化：

- `val/loss` 的随机波动减小；
- 不同 epoch 的验证指标更容易直接比较；
- EarlyStopping 的判断更稳定；
- 最佳 checkpoint 的选择更可靠；
- 同一 checkpoint 重复验证或测试时可以得到一致结果；
- `test/loss` 是八次采样的平均结果，比原来的单次结果更有代表性。

固定采样不能消除模型训练本身造成的波动，也不能保证验证损失单调下降。它只移除了评估噪声和时间区间每轮重新变化所引入的一部分方差。

### 5.3 对运行时间的影响

训练步骤仍为 `K=1`，所以训练 batch 的计算量基本不变。

评估阶段需要重复执行完整的 MeanFlow loss 和 JVP：

| 阶段 | 原采样次数 | 当前采样次数 | 单个 batch 的理论计算量 |
| ---- | ---------: | -----------: | ----------------------: |
| 训练 |          1 |            1 |                基本不变 |
| 验证 |          1 |            4 |               约为 4 倍 |
| 测试 |          1 |            8 |               约为 8 倍 |

总训练耗时不会直接变为四倍，因为只有验证阶段增加计算量；实际增幅取决于验证频率和验证集大小。

### 5.4 对历史结果的影响

该修改只对修改后的验证和测试运行生效，不会改变已有 checkpoint 的模型参数。

历史运行中记录的随机单次 `val/loss` 和 `test/loss`，与当前固定多次采样得到的指标不属于完全相同的评估口径，因此不应直接混合比较。如果需要重新评价旧 checkpoint，可以使用当前代码重新执行验证或测试，无需重新训练模型。

如果需要让 EarlyStopping 和最佳 checkpoint 选择也受益于稳定指标，则必须使用当前代码重新训练，因为历史训练过程中的 checkpoint 选择已经由原来的随机单次 `val/loss` 决定。

## 6. 最终状态

B2 当前形成了明确分工：

```text
训练：随机 K=1
  └─ 保留训练目标的随机覆盖范围和原训练速度

验证：固定 K=4
  └─ 降低指标方差，用于 EarlyStopping 和最佳 checkpoint 选择

测试：固定 K=8
  └─ 使用独立随机流，获得更稳定、更有代表性的最终指标
```

该修改没有改变 MeanFlow 网络结构、损失公式、时间区间分布或一步生成方式，只调整了验证和测试阶段对随机目标的估计方式。
