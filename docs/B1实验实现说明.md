# B1 条件 Flow Matching 实验实现说明

> 更新时间：2026-09-01

## 1. 实验定位

当前项目中的 B1 是一个 Mel 域的普通条件 Flow Matching 语音转换基线，整体结构为：

```text
VCTK 音频
  ├─ 目标 80 维 log-Mel → Flow Matching 训练目标 x₁
  ├─ FastU2++ → 256 维内容特征 c
  └─ WavLM Large + ECAPA-TDNN → 256 维说话人向量 s

h = Fuse(c, s)
vθ = UNet(xₜ, t, h)
```

训练阶段采用同一条目标语音的内容特征、说话人向量和 Mel 进行自重构。预测阶段则组合源语音的内容特征与参考语音的说话人向量，实现零样本语音转换。

该实现属于 MeanVoiceFlow 风格的受控 B1 基线，不是 MeanVoiceFlow 官方代码的逐行复现。它只实现普通条件 Flow Matching，不包含伪源语音、零输入重构、条件扩散输入或 Mean Flow 目标。

## 3. 数据集和声学特征

### 3.1 VCTK 输入

数据加载器从以下目录读取 VCTK：

```text
VCTK/
├── txt/
└── wav48_silence_trimmed/
```

默认使用 `mic1` 音频。音频读取后执行：

1. 多声道平均为单声道；
2. 重采样到 22050 Hz；
3. 训练阶段对超过 10 秒的语音随机裁剪，短语音保留原长度；
4. 验证和测试阶段对超过 10 秒的语音从开头确定性裁剪；
5. 一个批次内动态补齐到该批次的最长语音。

### 3.2 目标 Mel

B1 的目标是项目自己计算的 80 维 log-power Mel，不使用 MeanVC 内部 Mel 定义。

| 参数              |   当前值 |
| ----------------- | -------: |
| sample rate       | 22050 Hz |
| Mel bins          |       80 |
| FFT size          |     1024 |
| window length     |     1024 |
| hop length        |      256 |
| minimum frequency |     0 Hz |
| maximum frequency |  8000 Hz |
| window            |     Hann |
| STFT center       |   `true` |
| log floor         |   `1e-5` |

计算过程为：

$$
X = \operatorname{STFT}(x),
$$

$$
M = F_{\mathrm{mel}} |X|^2,
$$

$$
x_1 = \log\!\bigl(\max(M, 10^{-5})\bigr).
$$

得到的 `x₁` 形状为：

```text
[batch, 80, frames]
```

由于 STFT 使用 `center=true`，10 秒音频最多产生约 862 帧，因此：

$$
x_1 \in \mathbb{R}^{B \times 80 \times T},
\qquad T \leq 862.
$$

不同长度语音会在批内补零，并通过 `mel_attention_mask` 排除填充帧。

## 4. 离线条件特征

### 4.1 内容特征

内容编码器使用 MeanVC 的冻结 FastU2++：

```text
输入语音 → 16 kHz → 80 维 Kaldi FBank → FastU2++ → 256 维 BNF
```

当前流式参数为：

| 参数                | 当前值 |
| ------------------- | -----: |
| decoding chunk size |      5 |
| left chunks         |      2 |
| subsampling         |      4 |
| context             |      7 |
| 输出通道            |    256 |
| 时间上采样倍数      |      4 |

完整语句内容特征保存为：

```text
data/meanvc_features/vctk/content/<utterance_id>.pt
```

张量形状为：

```text
[256, content_frames]
```

### 4.2 说话人特征

说话人编码器使用：

```text
WavLM Large + ECAPA-TDNN
```

每条语音生成一个 256 维说话人向量，保存为：

```text
data/meanvc_features/vctk/speaker/<utterance_id>.pt
```

张量形状为：

```text
[256]
```

B1 不使用独立的长声学提示。训练使用目标语音自身的说话人向量，预测只读取参考语音预先缓存的说话人向量，不加载或计算参考语音的 Mel。

### 4.3 缓存格式和裁剪对齐

离线脚本以 `float16` 保存特征，训练加载后转换为 `float32`。

内容特征按完整语句提取。训练随机裁剪波形时，数据集根据波形裁剪起点和完整语句长度，按时间比例同步裁剪内容特征：

$$
f_{\mathrm{start}} =
\operatorname{round}\!\left(
\frac{n_{\mathrm{start}}}{N} T_c
\right),
$$

$$
f_{\mathrm{end}} =
\operatorname{round}\!\left(
\frac{n_{\mathrm{start}} + n_{\mathrm{crop}}}{N} T_c
\right).
$$

其中：

- $N$ 是完整语句重采样后的采样点数；
- $n_{\mathrm{start}}$ 是随机裁剪起点；
- $n_{\mathrm{crop}}$ 是裁剪后的采样点数；
- $T_c$ 是完整内容特征帧数。

这样可以让随机音频片段与缓存内容特征保持近似时间对应。

## 5. 条件融合

训练时使用：

$$
c = E_c^{\mathrm{fixed}}(x_{\mathrm{target}}),
$$

$$
s = E_s^{\mathrm{fixed}}(x_{\mathrm{target}}).
$$

预测时使用：

$$
c = E_c^{\mathrm{fixed}}(x_{\mathrm{source}}),
$$

$$
s = E_s^{\mathrm{fixed}}(x_{\mathrm{reference}}).
$$

`CachedConditionEncoder` 先把每条内容特征线性插值到目标 Mel 有效长度，再将说话人向量复制到所有时间帧：

$$
\widetilde{s}_{:,t} = s.
$$

融合过程为：

$$
h = \operatorname{SiLU}\!\left(
\operatorname{GroupNorm}\!\left(
\operatorname{Conv}_{1 \times 1}\!\left(
[\operatorname{Align}(c), \tilde{s}]
\right)
\right)
\right).
$$

当前维度为：

```text
内容特征：       [B, 256, T_c]
说话人特征：     [B, 256]
拼接特征：       [B, 512, T]
融合条件 h：      [B, 128, T]
```

填充位置最终通过目标 Mel mask 置零。

## 6. B1 Flow Matching 目标

对每条干净目标 Mel $x_1$，采样：

$$
x_0 \sim \mathcal{N}(0, I),
$$

$$
t \sim \mathcal{U}(0, 1).
$$

采用线性概率路径：

$$
x_t = (1 - t)x_0 + t\,x_1.
$$

该路径的真实速度为常量：

$$
u_t = \frac{\mathrm{d}x_t}{\mathrm{d}t} = x_1 - x_0.
$$

模型接口为：

$$
v_\theta(x_t, t, h).
$$

训练目标是带有效帧掩码的均方误差：

$$
\mathcal{L}_{\mathrm{B1}} =
\frac{
\sum_{b,c,t} m_{b,t}
\bigl(v_\theta(x_t, t, h)_{b,c,t} - (x_1 - x_0)_{b,c,t}\bigr)^2
}{
C \sum_{b,t} m_{b,t}
}.
$$

其中 $C=80$，$m$ 是目标 Mel 的有效帧 mask。

训练、验证和测试阶段都记录同一个重构 Flow Matching loss：

```text
train/loss
val/loss
test/loss
```

## 7. 速度场 U-Net

当前速度场使用 FastVoiceGrad 风格的一维 U-Net，输入为：

```text
x_t: [B, 80, T]
t:   [B]
h:   [B, 128, T]
```

输入处先拼接 $x_t$ 和 $h$：

```text
[B, 208, T]
```

网络主要参数：

| 参数               | 当前值 |
| ------------------ | -----: |
| Mel channels       |     80 |
| condition channels |    128 |
| hidden channels    |    512 |
| time embedding     |    128 |
| kernel size        |      3 |
| downsampling       |   2 次 |
| upsampling         |   2 次 |
| 默认推理步数       |     50 |

12 个卷积层依次为：

01. 输入门控卷积；
02. 编码器卷积 1；
03. 下采样卷积 1；
04. 编码器卷积 2；
05. 下采样卷积 2；
06. 瓶颈卷积 1；
07. 瓶颈卷积 2；
08. 上采样转置卷积 1；
09. 解码器卷积 1；
10. 上采样转置卷积 2；
11. 解码器卷积 2；
12. 输出卷积。

结构特点：

- 所有卷积和转置卷积使用 Weight Normalization；
- 除最终输出卷积外，卷积输出使用 GLU 门控；
- 两级编码器与解码器之间使用加法跳跃连接；
- 连续时间嵌入经过 MLP 后注入各级隐藏层；
- mask 会同步缩放到每一级时间分辨率；
- 奇数帧长度在上采样后通过线性插值重新对齐。

网络输出为：

```text
predicted_velocity: [B, 80, T]
```

## 8. 推理方式

推理从与目标形状相同的高斯噪声开始：

$$
\hat{x}_0 \sim \mathcal{N}(0, I).
$$

使用显式 Euler 方法从 $t=0$ 积分到 $t=1$：

$$
\hat{x}_{k+1} = \hat{x}_k + \Delta t \cdot v_\theta(\hat{x}_k, t_k, h),
$$

$$
\Delta t = \frac{1}{K}.
$$

当前默认 $K=50$。最终输出是转换后的 80 维 Mel：

```text
[B, 80, T_source]
```

当前项目没有接入声码器，因此 B1 只输出 Mel，不能直接生成可播放波形。

## 9. 数据划分

B1 实验使用 `UnseenSpeakerSentenceSplit`。

测试说话人：

```text
p345, p347, p351, p360, p361,
p362, p363, p364, p374, p376
```

测试句子编号：

```text
002, 003, 005, 009, 010,
011, 012, 016, 017, 019
```

划分规则：

1. 测试集取指定测试说话人与指定句子编号的交集；
2. 训练和验证集排除全部测试说话人；
3. 训练和验证集同时排除测试句子编号；
4. 剩余每个说话人的语句使用固定种子打乱；
5. 每个说话人约 10% 的语句进入验证集，且至少保留 2 条验证语句；
6. 测试预测时参考语音从不同说话人中选择。

需要注意，`test_step()` 当前计算的仍然是目标语音自重构 loss；真正组合“源内容 + 不同说话人参考向量”的转换逻辑位于 `predict_step()`。

## 13. 当前实现边界与注意事项

### 13.1 不是严格官方复现

当前实现复用了 MeanVC 的冻结条件提取器，并采用 MeanVoiceFlow 风格的 B1 普通条件 Flow Matching 设计，但没有引入 MeanVC 或 MeanVoiceFlow 的完整训练系统。

### 13.2 没有声码器

当前输出是 Mel，尚未连接 HiFi-GAN 或其他 vocoder。因此当前只能训练声学 Flow Matching 模型，不能完成 Mel 到波形的最终合成。

### 13.3 测试 loss 不是转换质量指标

`test/loss` 与训练目标相同，使用目标自身的内容和说话人条件进行重构。它不能直接代表跨说话人转换质量。跨说话人转换需要通过 `predict_step()` 生成 Mel，并在后续加入声码器和客观/主观指标后评估。

### 13.4 缓存必须完整

DataModule 启动时只检查 `content/` 和 `speaker/` 目录是否存在。若某条语音缓存缺失，会在 DataLoader 读取该语音时抛出 `FileNotFoundError`。

### 13.5 Callback 监控指标

项目的通用 callback 默认监控：

```text
val/acc
```

而 B1 实验配置已单独覆盖为：

```yaml
monitor: val/loss
mode: min
```

因此 ModelCheckpoint 和 EarlyStopping 会根据 B1 的验证损失正常工作，同时不会影响其他使用 `val/acc` 的实验。

## 14. B1 与后续实验的关系

当前 B1 提供后续实验的统一基础接口：

```text
model(x_t, t, h)
```

后续实验可以保持 VCTK、Mel、离线内容特征、说话人特征和 U-Net 主干不变，只修改训练样本构造、条件输入或速度目标，从而进行受控对比。
