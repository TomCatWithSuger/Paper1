# 研究模板开发规范：模块边界、AI 工作流程与质量门禁

## 1. 定位与执行状态

目标不是增加模型子目录，而是让使用者和 AI 可以回答：新代码放在哪里、由谁创建对象、哪些依赖合法、如何确认组合正确，以及哪些检查必须通过才能合并。

本项目根 README 引用了 `ashleve/lightning-hydra-template`；该上游提供 Lightning、Hydra、训练入口、配置和测试脚手架。本文在此基础上定义研究模板自己的工程约束，不宣称这些约束已由上游全部提供。

本文规定新模板的目标门禁。当前 Paper1 已有分层实现和模型测试，但以下状态必须区分：

| 内容                                 | 当前状态                                                                                  |
| ------------------------------------ | ----------------------------------------------------------------------------------------- |
| 四层模型、Hydra 组合、代表性契约测试 | 已有实现，参见模型结构说明                                                                |
| Black/isort/Flake8、注释覆盖等       | 完整 pre-commit 与 `make lint-changed` 本地通过，后者覆盖未跟踪的新文件                   |
| AI 入口与新增实验 Skill              | 已接入并完成离线演练；自动发现仍取决于客户端支持                                          |
| Import Linter 架构门禁               | 已接入正式配置，本地全图 3 项契约通过                                                     |
| Pylint 500 行门禁                    | 全仓检查通过；500/501 物理行边界自测通过                                                  |
| Pyright 类型门禁                     | 扫描 179 个文件，0 错误、0 警告；未降低类型规则或添加忽略名单                             |
| 文件说明与章节检查                   | 全仓模块说明与章节顺序检查通过                                                            |
| 统一门禁与门禁自测                   | `python scripts/quality.py all` 通过；12 项正反例、环境版本一致性及缺工具、空集合自测通过 |

本文是模块划分与开发质量的规则来源；[模型结构说明](src_models%E7%BB%93%E6%9E%84%E8%AF%B4%E6%98%8E.md)记录现有实现；[模板提取指南](%E9%80%9A%E7%94%A8%E7%A0%94%E7%A9%B6%E6%A8%A1%E6%9D%BF%E6%8F%90%E5%8F%96%E6%8C%87%E5%8D%97.md)说明如何拆出新仓库。三者不应混为“已通过的验收”。上表是 2026-11-03 的运行快照，不是永久基线或豁免名单。

本地离线回归为 278 项通过、4 项未选中，覆盖模型、分析、配置、非 MNIST 数据、辅助工具及模拟下载脚本；真实 CLI 的 CPU 合成实验冒烟也已通过。三平台锁文件已重建并通过离线核验。没有执行需下载的 MNIST 测试、慢测或完整论文训练；远端 CI 和跨平台环境安装仍须独立验收。

## 2. 写代码前先判断职责

不要先找一个看起来相近的算法目录。先判断这段代码的输入、输出、状态、副作用和变化原因。

| 需求                                   | 归属                     | 选择依据                                        |
| -------------------------------------- | ------------------------ | ----------------------------------------------- |
| 文件读取、样本转换、划分、Batch 生产   | `src/data/`              | 面向数据来源和数据契约，不调用具体 Method       |
| 小型注意力、嵌入、残差或融合计算       | `src/models/components/` | 局部计算接口，不承担完整学习目标                |
| 具有稳定输入输出的可学习计算单元       | `src/models/networks/`   | 独立前向计算，可组合多个子网络                  |
| 目标、扰动、损失组合、生成、更新阶段   | `src/models/methods/`    | 定义学习算法，不调用 Lightning 生命周期         |
| Batch 适配、日志、反传执行、优化器推进 | `src/models/modules/`    | 由训练生命周期和执行契约决定                    |
| 可复用确定性路径、数值积分等           | `src/models/algorithms/` | 数学语义稳定，不知道具体实验                    |
| 跨方法复用的损失                       | `src/losses/`            | 只依赖 Tensor 与数学计算；专用目标可留在 Method |
| 优化与学习率调度辅助                   | `src/optim/`             | 不读取论文数据或构造具体 Network                |
| 指标计算、实验结果聚合与比较           | `src/analysis/`          | 通过评估接口或结果记录访问模型，不读取私有层    |
| 选择实现和参数                         | `configs/`               | 组合配置，不在 YAML 中复制算法逻辑              |
| 命令行解析与调用                       | `scripts/`               | 薄入口，不成为第二套业务实现                    |

分类例子：换 Transformer 主干通常只改 Network 和配置；改速度目标为平均速度目标应改 Method；增加 G/D 交替更新需要对应 Module 执行能力；换语料只要 Batch 契约兼容，就不应复制训练 Module。

## 3. 如何确定文件与模块边界

一个模块应能用一句话描述对外职责，其依赖和状态都服务于该职责。若必须用多个无关的“以及”才能说明，应考虑拆分。

拆分顺序：先按独立变化原因，再按输入输出契约，最后按文件大小。典型边界是数据读取/变换、目标构造/执行、指标计算/结果展示，而不是机械切成 `part1`、`part2`。

公共组件的提炼条件：有两个真实调用场景，或明确的独立数学/契约测试价值；接口稳定；减少重复而不是制造适配层。只有一个 Network 使用的私有辅助类可以与其放在同一文件。

禁止为绕过长度限制压缩空行、删必要说明、塞进通用 `utils.py`、复制状态或新增循环导入。拆分时保留必要的公开导出，并验证状态键名和配置目标是否变化。

## 4. 三种关系必须分别定义

### 4.1 代码导入关系

| 调用方           | 允许依赖                                  | 禁止依赖                                            |
| ---------------- | ----------------------------------------- | --------------------------------------------------- |
| Component        | PyTorch、低层 Component、基础计算接口     | 具体 Network、Method、Module、训练框架              |
| Network          | Component、公共计算接口                   | Method、Module、Trainer、配置入口、数据加载流程     |
| Algorithm / Loss | Tensor、基础数学工具、必要接口            | 具体 Network/Method、Lightning、实验配置            |
| Method           | 网络能力接口、Component、Algorithm、Loss  | Lightning Module、Trainer、训练入口、原始数据加载器 |
| Module           | Method 能力接口、训练框架、指标、优化工具 | 具体 Network 内部层、重复算法公式                   |
| Data             | Dataset 工具、预处理和数据格式            | 具体 Method 与训练 Module                           |
| Analysis         | 公开评估接口、指标与结果记录              | 模型私有层、训练入口副作用                          |
| 组装入口         | 公开可实例化组件及配置                    | 在构造时启动正式训练或隐式下载                      |

上层可以依赖下层，不代表所有跨层访问都合理。Module 为编译或保存访问 Method 的公开能力，与直接知道 `network.encoder.block3` 完全不同。

配置装配、评估入口和测试可以直接使用各层的公开接口。算法不得通过中间 `utils` 间接导入上层；也不得用动态导入躲过检查。

### 4.2 对象构造关系

Hydra 是对象组装工具，构造函数注入是代码接口。Method 接收 Network 或工厂，不在业务分支里按字符串识别 `UNet`、`DiT` 再构造实现。

```yaml
method:
  _target_: src.models.methods.generative.flow.flow_matching.FlowMatching
  integration_steps: 10
  network:
    _target_: src.models.networks.dense.field.DenseTimeField
    input_shape: [1, 28, 28]
    hidden_dims: [32, 32]
```

这只是当前可实例化模型的 Method 配置片段；完整训练还需要 Module、数据和执行配置。外部组装后，Method 只通过约定的前向能力使用网络。

优化器继续使用 `_partial_: true` 延迟绑定参数。对象需要共享时，在唯一组装位置构造一次并显式注入；重复的 YAML 插值或两个 `_target_` 节点不等于共享同一实例。测试要检查对象身份和参数身份。

只实例化可信配置；禁止把任意用户输入当作 `_target_` 执行。配置模式和类型校验用于尽早发现错误，但不能证明 Shape、梯度与目标语义正确。

### 4.3 参数与状态所有权

Component、Network、Method 均可拥有 Parameter 和 Buffer。拥有者负责注册，执行层负责使用。共享编码器、Teacher/Student、EMA 等需分别说明参数共享、冻结、Buffer 更新与保存方式。

Module 不重复注册已经由 Method 持有的网络。参数角色暴露是公开能力接口，不要求所有 Method 都使用 GAN 的角色名或阶段格式。

## 5. 是否需要额外的连接框架

| 工具                              | 用途                                    | 本模板选择                                 |
| --------------------------------- | --------------------------------------- | ------------------------------------------ |
| Hydra / OmegaConf                 | 配置组合、递归实例化、工厂与结构化配置  | 优先复用现有实现，不再手写通用注册中心     |
| Import Linter                     | 用 layers/forbidden 等契约检查导入图    | 建议作为架构门禁；它不负责创建对象         |
| Protocol / dataclass + 类型检查器 | 描述能力接口和结构化数据                | 在稳定边界按需使用，不统一所有 forward     |
| Dependency Injector               | 工厂、单例、资源生命周期与替换          | 当前不默认引入；有服务生命周期需求时再评估 |
| pytest                            | 验证实例化、身份共享、Shape、梯度和恢复 | 必需；不能由依赖注入容器代替               |

没有一个包可以自动判断“这段代码属于 Method 还是 Network”。工具自动组装和自动检查，人或 AI 按本规范决定职责。额外 DI 容器也不能代替 `nn.Module` 的参数注册和设备迁移。

## 6. AI 使用方式

统一规则只维护一份，其他入口引用它，避免多份指令互相矛盾：

| 载体                                              | 内容                                     | 不承担的职责               |
| ------------------------------------------------- | ---------------------------------------- | -------------------------- |
| 根 `AGENTS.md`                                    | 全局限制、必读规则、质量要求、Skill 入口 | 不塞完整算法百科           |
| 本开发规范                                        | 路由表、边界、依赖、文件模板和验收       | 不声称自动强制执行         |
| `.github/skills/add-research-experiment/SKILL.md` | 新实验/模型接入的操作步骤                | 不保证被所有客户端自动加载 |
| 可选文件级 Instructions                           | 特定路径的少量额外规则                   | 不重复全部 AGENTS 内容     |
| 可选自定义 Agent                                  | 明确需要工具隔离的审查任务               | 当前无需为每一层建立 Agent |
| pre-commit + CI                                   | 可重复、确定性的代码质量阻断             | 不判断所有数学语义         |

Skill 的自动发现取决于客户端支持和配置，可显式要求使用该 Skill。AI 遵守文档属于行为约束，不等于技术隔离；最终以实际命令和测试结果为准。

## 7. 新实验的固定开发流程

1. 给出任务的输入、输出、训练目标、预测/生成语义和最小成功条件；缺少决定性信息再询问。
2. 先读相邻实现和测试，用路由表列出新增/复用的 Data、Network、Method、Module、Config 和 Test。
3. 为新增公开边界写明 Shape、DType/Device、Mask、随机数、梯度和状态归属；明确哪些变化需要新 Module。
4. 说明对象组装点、允许导入和参数角色。优先依赖公开能力，不导入具体实现来做类型分支。
5. 基于本地合成数据实现最小路径；禁止未授权安装/下载；不先开正式训练。
6. 每完成一个行为切片立即运行聚焦测试，再完成 Hydra 组装、预测和恢复验证。
7. 执行格式、静态检查、依赖图、长度与测试门禁；审查例外是否有理由，禁止全局关闭规则。
8. 更新实验说明，记录运行命令、配置、指标语义和验证限制，报告实际执行结果。

只有模型、数据、配置、测试和说明一起满足约定，才称为“接入完成”；仅新增一个类或目录不算完成。

## 8. Python 文件模板与注释规则

沿用根 AGENTS 的七段结构，但空章节省略；顺序保持稳定，不给每个类机械重复七段。模块说明必须交代职责、公开能力和重要状态/副作用。

```python
"""模块说明：
- 负责同形状张量的均方误差计算。
- 对外提供 mean_squared_error；不保存参数，不访问文件或训练框架。
"""

# ====================
# 1. Imports
# ====================

import torch


# ====================
# 6. Public API
# 对外提供的函数
# ====================

def mean_squared_error(prediction: torch.Tensor, target: torch.Tensor) -> torch.Tensor:
    """计算示意回归误差。

    输入：同形状、同设备的非空浮点 Tensor；本接口不接收 Mask。
    输出：可反传的标量均方误差，不修改输入。
    """
    if prediction.shape != target.shape or prediction.numel() == 0:
        raise ValueError("prediction 与 target 必须同形状且非空")
    return (prediction - target).square().mean()
```

上例仅示意结构，不新增另一个生产损失函数。真实函数应以实际行为命名，不能把未实现的能力写进名称或 docstring。

公开函数/类添加类型标注；张量注释解释轴含义、Mask 极性、空输入策略和返回语义。复杂计算解释“为何这样做”和梯度边界，不逐行复述赋值。中文说明为主；不要求注释覆盖率工具判断中文语义是否正确。

生产文件与测试原则上都不超过 500 物理行，含注释、空行和 docstring；不计外部/vendor、生成产物或 Notebook 原始 JSON，但应明确排除路径。超过约 350 行时评估职责，超过 500 行必须拆分或取得具体例外批准，不能自行扩大门槛。

## 9. 质量门禁与工具分工

当前保留 Black/isort/Flake8 等已有格式工具链，新增 Pyright、Import Linter、Pylint 长度规则与模板检查，再由 pre-commit 与 CI 调用。未安装 Ruff；提取新模板时可独立评估是否统一迁移，不能同时运行互相改写的两套格式化器。

| 门禁                     | 建议工具                                | 失败条件                                                |
| ------------------------ | --------------------------------------- | ------------------------------------------------------- |
| 格式、导入、常见静态错误 | Ruff；迁移前保留现有工具链              | 未格式化、未定义名称、错误导入及选定规则违规            |
| 类型与能力接口           | Pyright                                 | 公共契约不匹配；范围与第三方存根例外显式配置            |
| 架构依赖                 | Import Linter                           | 下层反向依赖、核心依赖 Lightning/入口、禁止的跨模块访问 |
| 文件长度                 | Pylint `too-many-lines`                 | 超过 `max-module-lines=500`；上线前验证计数边界         |
| docstring                | Ruff D 规则或现有 Interrogate           | 缺少指定公开接口说明；语义正确性仍需审查                |
| 配置与行为               | pytest                                  | 组装、形状、梯度、随机性、状态或恢复失败                |
| 项目特定文件模板         | 小型 token/AST 检查，仅在明确必要时添加 | 缺模块说明、章节顺序错误；不重复实现通用 lint           |
| 资源与秘密               | pre-commit 现有检查与离线测试           | 私钥、大文件、隐式下载或访问个人数据                    |

格式、依赖分析和长度检查优先使用成熟工具。只有“七段中文章节”等仓库特有规则缺乏合适检查器时才补小检查；不能把自写正则 import 扫描器当作完整依赖检查。

### 9.1 Import Linter 配置设计

正式配置位于根目录 [.importlinter](../../.importlinter)，本地已验证下列三项契约。外部导入检查必须启用；layers 允许上层访问较低层，因此还需 forbidden 精确限制和行为测试。

```ini
[importlinter]
root_package = src
include_external_packages = True

[importlinter:contract:model-layers]
name = Model layer direction
type = layers
layers =
    src.models.modules
    src.models.methods
    src.models.networks
    src.models.components

[importlinter:contract:framework-free-core]
name = Core does not import the training framework
type = forbidden
source_modules =
    src.models.methods
    src.models.networks
    src.models.components
    src.models.algorithms
    src.losses
forbidden_modules =
    lightning
    pytorch_lightning
    src.train
    src.eval
    src.data
    src.analysis

[importlinter:contract:independent-math]
name = Math does not depend on concrete models
type = forbidden
source_modules =
    src.models.algorithms
    src.losses
forbidden_modules =
    src.models.methods
    src.models.networks
    src.models.modules
```

迁移时根据保留包补全规则；不存在的包不能盲目留在配置中。统一入口会拒绝 `src` 中缺少 `__init__.py` 的源码目录，防止依赖图静默漏扫。静态导入检查不能覆盖 YAML 的 `_target_`、反射或对象属性访问，所以同时执行 Hydra 实例化与参数身份测试。

### 9.2 500 行检查设计

统一入口使用已安装的 Pylint 对收集到的源码逐项检查，覆盖 `src`、`tests`、`scripts` 和 `configs`。已通过包含空行与注释的 500/501 行边界测试；禁止用全局 `disable` 或排除整个业务目录绕过规则。

### 9.3 本地与 CI

本地、pre-commit、CI 调用相同的 `python scripts/quality.py all`。PR 即使仅修改一个文件，也完整扫描导入图、长度、类型和模板规则。模型的配置组合与训练契约由测试工作流另行运行。

工具缺失、配置损坏或零测试收集必须失败，不能打印警告后返回成功。pre-commit 初次运行可能下载环境，仍需遵守项目下载授权规则。

门禁自测位于 [tests/quality/test_gates.py](../../tests/quality/test_gates.py)，使用临时目录验证合法/反向导入、正式配置的直接/间接框架依赖、数学层反向依赖、500/501 行、错误返回类型、模板规则，以及缺工具、缺 Node、零源码或零测试时失败；同时检查环境声明与质量工具版本一致性。当前 12 项通过。Shape 与梯度仍由模型契约测试验证。
