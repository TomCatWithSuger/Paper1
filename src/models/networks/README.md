# Networks 分类说明

`networks` 按神经网络的主要架构家族分类，不按学习目标、生成算法、数据集或 Lightning 训练流程分类。

```text
networks/
├── dense/                      # 全连接网络
│   ├── classifier.py
│   ├── autoencoder.py
│   ├── adversarial.py
│   └── field.py
├── unet/                       # U-Net 网络
│   ├── waveform.py
│   └── conditional.py
└── transformer/                # Transformer 网络
    ├── dit.py
    └── conditional.py
```

## 核心原则

1. 顶层子目录按主要架构家族划分，例如 Dense、U-Net 和 Transformer。
2. 架构目录内按完整网络的结构变体或前向接口划分文件。
3. Network 只负责可学习函数及前向计算，不负责训练目标和生成流程。
4. 数据模态、条件形式和算法用途可以影响文件名或接口，但不决定顶层目录。
5. 同一 Network 可以被多个满足其输入输出契约的 Method 复用。

该目录是一套工程分类。混合架构应按承担主要计算的主干归类，并在文件名和说明中表达其他结构特征。

## 层级边界

| 层级      | 职责                                                           |
| --------- | -------------------------------------------------------------- |
| Component | 可复用的局部计算单元，例如卷积块、Transformer Block 和时间嵌入 |
| Network   | 组合 Component，形成具有明确输入输出契约的完整参数化函数       |
| Method    | 组织一个或多个 Network，定义目标、损失、扰动、路径及生成过程   |
| Module    | 管理 Lightning 生命周期、Batch 适配、日志和优化器              |

Network 可以：

- 执行输入投影、特征提取、条件融合和输出预测。
- 接收由 Method 构造的时间、噪声等级、条件特征和掩码。
- 为复合结构提供 `encode()`、`decode()` 或 `discriminate()` 等确定性前向接口。
- 保存网络结构需要的维度、通道数和输入形状信息。

Network 不应：

- 计算训练损失或决定监督目标。
- 随机采样时间、噪声、潜变量或概率路径。
- 实现扩散反演、Langevin 动力学或 ODE 积分循环。
- 访问 Lightning、Trainer、优化器、日志或原始 Batch 字段。
- 根据自己被 DDPM、Flow Matching 或其他 Method 使用而改变训练流程。

时间嵌入、条件注意力和掩码传播属于前向计算，可以保留在 Network 中；时间如何采样、条件如何构造以及输出代表何种算法目标由 Method 决定。

## 当前架构家族

### `dense/`

以 `Linear` 层为主要计算结构，适合固定尺寸输入或展平后的张量。

| 文件             | 网络职责                                  |
| ---------------- | ----------------------------------------- |
| `classifier.py`  | 从固定尺寸输入预测输出向量                |
| `autoencoder.py` | 提供确定性或高斯参数化的编码器—解码器结构 |
| `adversarial.py` | 提供生成器、判别器及其组合网络            |
| `field.py`       | 根据状态和时间或噪声条件预测同形状张量场  |

`autoencoder.py` 和 `adversarial.py` 描述的是复合网络结构与接口，不表示其训练目标属于 Network；重构、KL 或对抗损失仍由 Method 定义。

### `unet/`

以多尺度编码、瓶颈、解码和跳跃连接为主要结构。

| 文件             | 网络职责                                       |
| ---------------- | ---------------------------------------------- |
| `waveform.py`    | 一维波形 U-Net 前向映射                        |
| `conditional.py` | 融合时间字段、条件特征和有效帧掩码的条件 U-Net |

条件 U-Net 可以被不同流方法复用。新增条件字段时，应优先保持统一的 `times` 映射接口，不为每个算法复制一套 U-Net。

### `transformer/`

以自注意力和 Transformer Block 为主要计算结构。

| 文件             | 网络职责                                            |
| ---------------- | --------------------------------------------------- |
| `dit.py`         | 接收连续时间条件的一维 DiT 前向映射                 |
| `conditional.py` | 融合序列条件、时间条件和掩码的 Transformer 前向映射 |

DiT 虽常用于扩散或流模型，但其目录归属由 Transformer 主干决定，而不是由生成算法决定。

## Network 与 Component 的边界

以下情况通常属于 Network：

- 形成完整输入到预测结果的映射。
- 拥有任务所需的输入投影、主干和输出投影。
- 可以由 Hydra 配置直接注入 Method。

以下情况通常属于 Component：

- 只是残差块、注意力块、门控卷积或嵌入层。
- 缺少独立、稳定的完整模型输入输出契约。
- 会被多个 Network 组合使用。

只被一个 Network 使用且与其结构强耦合的小型辅助类可以留在同一文件中，不必为每个内部模块创建 Component。

## 输入输出契约

Network 能否互换取决于前向契约，而不是是否位于同一架构目录。契约至少包括：

- 输入张量的维度、通道顺序和形状。
- 时间或噪声条件的字段名称及形状。
- 条件特征和掩码的含义。
- 输出张量的形状及参数化方式。
- Method 需要调用的额外接口，例如 `decode()` 或 `discriminate()`。

同一家族中的两个 Network 若契约不同，不能直接互换；不同家族的 Network 若契约一致，则可以由同一个 Method 通过配置切换。

## 新 Network 如何归类

按以下顺序判断：

1. 主要计算主干是否属于现有的 Dense、U-Net 或 Transformer 家族？是则放入对应目录。
2. 是否只是已有 Network 的局部可复用单元？是则放入 `components/`，而不是 `networks/`。
3. 是否包含损失、随机扰动或采样循环？这些逻辑应移入 Method 或独立 Sampler、Scheduler、Solver。
4. 是否形成新的稳定架构家族？只有现有目录无法准确表达时才新增顶层子目录。
5. 是否只是条件版、数据模态版或输出参数化不同？通常新增文件或类，不新增顶层目录。

命名时优先描述架构和前向契约，避免只使用实验名、论文名或 Method 名称。新增实现前应确认现有 Network 不能通过配置或小范围扩展复用。
